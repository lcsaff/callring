# 规则来电铃声与来电管理

独立 Android 应用，包名 `com.greatwall.callring`，当前版本 **0.3.0**（`versionCode 3`；版本号由根 `version.properties` 单一来源驱动，标签统一为 `v<versionName>`，如 `v0.3.0`）。规则号码完整匹配 `3[0-9]{4}`，例如 `31234`；接听使用手机原有电话应用。

## 使用

首页、档案、沟通、设置四个入口采用 Kotlin + Compose，宽窄窗口使用相同导航。首页显示当天工作日、休息日或法定节假日，节假日期间显示节日名称，另行显示当前工作状态，并提供请假管理。号码档案、报表和职位列表在档案中管理；配置开关统一放在设置。首次使用请在设置的“运行状态与权限”检查电话状态、通知和来电识别角色。

页面交互统一使用 Material 3 顶部应用栏、日期/区间选择器、表盘与键盘时间选择器和职位下拉菜单。所有工作日共用上班、午休开始、午休结束和下班四个时间点；自定义免打扰时段仍支持逐条编辑和跨午夜。保存结果使用 Snackbar，输入错误就地提示。删除与恢复默认需要确认，未保存表单退出可保存、放弃或继续编辑。窗口大小变化时自动切换底部导航与侧边导航，内容宽度和键盘避让同步适配。

页面密度已统一收紧：页边距 16dp、常用区块间隔 8dp、设置卡片内边距 12dp，保留 Material 控件默认触摸区域。原有主题色、深浅模式与评分配色规则继续生效。

时区仅在“设置 → 工作时间”中通过下拉列表选择，其它页面按配置时区显示日期时间，不再展示时区标签。日期与时间入口分行显示标签和数值，弹窗支持键盘输入及短窗口滚动。刷新和保存时不再插入顶部进度条，避免内容上下跳动。

首页不显示最近来电、桌面小组件按钮或设置快捷入口。桌面小组件仍可通过系统组件选择器添加。档案中的号码查询同时显示规则匹配结果，未匹配规则的有效号码也可查看报表。

- **档案与报表**：搜索、新建、编辑号码、姓名、部门和职位，设置白名单。职位从配置选项选择；配置“我的当前职位”后显示 ↑ 高于我、↓ 低于我、＝ 同级、— 未设置。层级数字越小职位越高，不同职位允许同级。
- **设置**：个人信息排在首位，另有来电处理、工作与评分、录音与 AI、显示、系统与支持分类；管理统计、悬浮窗、铃声、统一工作时间、时区、节假日同步、评分、我的职位、运行权限和外观。请假与免打扰在首页管理，职位列表在档案管理，不再提供手动指定日期调整。暂停统计保留历史；关闭规则铃声不会关闭统计或免打扰。
- **免打扰**：首页提供快捷开关，左侧“自定义”按钮打开时段设置弹窗，支持按星期设置多段时间与跨午夜时间。关闭保留时段，再次开启恢复上次模式，重启后仍保留；首次开启使用全部非工作时间静音。自定义模式要求同时满足非工作时间与静音时段；默认只处理规则号码，可扩大至系统交付的全部可筛选来电。白名单绕过应用免打扰，仍遵守手机静音、振动、系统勿扰和音量设置。
- **来电悬浮窗**：授权并开启后，来电卡片展示档案、职位比较、评分、次数、工作分类和当次决策，支持拖动、收起、编辑、白名单及报表入口。锁屏隐藏个人信息；仍在响铃时解锁可显示，已结束的摘要不会重新自动弹出。
- **桌面组件**：从桌面组件选择器添加 Glance 组件并绑定号码。小尺寸显示姓名/号码与评分，大尺寸补充部门/职位；提供报表和明确的“加入/移出白名单”，大尺寸另有更换号码与刷新。每个组件独立绑定。

外观预设为联通红 `unicom_red`（`#E60012`，默认）、天空蓝 `sky_blue`（`#1976D2`）与青绿 `teal_green`（`#008577`），支持任意 RGB/HEX 自定义主色，以及跟随系统、浅色、深色模式。评分始终为 **80 分及以上绿色、60–79 分黄色、低于 60 分红色、暂无评分中性色**，不随主色改变。

预设主题作为自定义颜色的快捷入口：选择预设后立即更新 HEX、RGB 滑块、预览和应用主色，保持当前深浅模式。原来保存的预设设置继续兼容。

主按钮保留选定的原始 RGB，深色模式也使用同一原色。背景、卡片及通用状态容器采用中性色；文字、图标和链接独立适配对比度，黑白自定义按钮补充边框。

此次直接切换至新 UI 与新组件身份；旧桌面组件需要移除后重新添加。应用数据库、原设置和已导入音频继续保留。

## 工作时间、评分与数据

默认所有工作日统一使用 `09:00–12:00,13:00–18:00`，开始包含、结束不包含，午休和下班后不工作。日历自动识别普通工作日、休息日、法定节假日；补班日按工作日使用同一时间表。请假不改变当天日历类型，只让对应期间不工作。新版编辑器不再提供逐星期、单独补班时段及指定日期调整；保存时统一后续工作时间，历史时间表和原始来电决策保留兼容。

内置 2026 年日历作为离线基础，并从 [holiday-cn](https://github.com/NateScarlet/holiday-cn) 按年同步依据国务院公告维护的数据；它是第三方数据源。启动时安排后台同步，成功后每周检查、失败后六小时重试，十月起尝试预取下一年；未公布的空白年份不会记为已核验。下载完成并通过校验后原子替换本地缓存，失败保留旧数据；来电判断不等待网络。设置中的“节假日同步”展示已缓存年份、来源和版本，支持主动同步。

常规工作安排修改影响之后来电；请假和日历可更正历史分类并重算评分，保留原始分类与响铃/静音决策。

打扰越严重，分数越低。默认公式为 `max(0, 100 − 非工作来电次数 × 5 − 短时间重复次数 × 2)`，相邻来电间隔不超过 10 分钟计一次重复。权重、间隔和观察天数可调整；无记录显示“暂无评分”。白名单和职位关系不改变评分公式。

悬浮窗与组件默认采用最近 30 天滚动评分。报表支持今天、近 7/30 天、自定义日期、分类筛选和分页，展示分类依据、通话结果及时长，区分未知与实际 0 秒；可通过系统文档选择器导出 CSV。系统通话记录与筛选事件仅在唯一匹配时关联，不确定记录保留待核对状态。

号码、档案、设置与明细存于应用私有数据库，禁止云备份/设备迁移。节假日同步下载公开数据；录音与自动分析默认关闭，启用自动分析或主动点击分析后，会将对应录音发送到配置的转写服务，将转写发送到配置的分析服务。主动使用“沟通”会发送应用完整业务文字，范围见下节。报表仅在用户主动导出时写出。完整数据语义见 [业务 API 契约 v1](docs/plans/UI业务API契约_v1.md)。

## AI 沟通与设置

“设置 → AI 设置”管理分析和转写连接、密钥、本地复制、连接测试及上下文预算；“录音设置”管理录音开关、自动分析、采集模式和系统目录。两页共享原有加密配置，保留已有连接和录音；仅提交编辑过的字段。并发修改不同字段会合并，同一字段冲突会保留草稿并提示。档案、免打扰、工作时间、评分、职位、请假及外观编辑也使用相同的字段合并规则。

在“沟通”发送消息会把应用完整业务文字、全文转写/分析、历史配置、审计、诊断、授权录音目录元数据和运行状态交给当前分析服务，可能产生费用。每次模型请求和业务操作后均重新采样完整21域；不会为适配容量删字段、摘要或省略工具。沟通不发送音频文件、私有文件路径、可调用 URI 或密钥；目录文件以本地短期句柄表示，密钥仅显示是否配置。完整性读取失败或容量不足会停止。此能力不能读取手机上的全部通讯录或未授权目录。

支持 OpenAI / Anthropic 兼容工具调用，共72项业务操作，复用原有校验和存储。需要文件、权限、角色、系统页面、删除确认或本地密钥输入时，等待前台用户操作；拒绝、取消、过期、结果未知分别显示。小组件“已发起”不等于已安装，后台任务“已排队”不等于已完成。操作成功后原页面、悬浮窗和组件通过同一变更通知刷新。

上下文客户端默认预算为 **49152**，输出预留 **4096**；context 可设8192–1048576，output 可设1024–16384且小于context。估算计入完整UTF-8请求、全部schema、历史、输出和安全余量，另设8MiB请求、1MiB回复和20000条数据上限。目录最多500节点、4层，两遍枚举一致才使用。49152是客户端限制，不承诺服务模型具备同等容量；服务端拒绝不会静默重试。旧配置缺失预算时使用新默认，已有显式32768等数值不会被升级覆盖。

密钥通过本地表单保留、替换或清除，不进入聊天及保存的界面状态。连接测试使用固定测试内容并可能计费。会话仅保留在当前进程；停止或新对话不会撤销已经保存的业务修改，进程退出后聊天不恢复。分析连接变化会停止当前请求并清理旧匹配历史。自动验收、72项操作证据和未实测边界见 [AI 沟通验收](docs/plans/AI沟通验收.md)。

首次配置时，先填写所选连接的地址和模型，再打开“本地编辑密钥”，填写密钥并保存；该连接草稿与密钥在同一次校验和事务中保存，取消不写入。沟通的服务标签显示下一次发送目标，发送仍会核对本次界面已显示的连接；变更后不会自动向未告知的目标发送。带工具的模型文字标为未经验证，实际操作以本地回执为准。删除、采纳与测试确认会显示本地读取的具体目标，目标变更会使旧确认失效。目录安全视图包含真实显示名和访问状态；无法查询时明确未知，不暴露目录 URI 或完整路径。

## 通话录音与 AI 归档

在“设置 → AI 设置”配置两组连接：转写使用 **OpenAI 兼容**接口；内容分析可选 **OpenAI / Anthropic 兼容**接口。每组填写 URL、API Key、Model；模型自由填写，可复制另一组连接参数。URL 是带版本和自定义前缀的 API 基础地址，例如 `https://example.com/proxy/v1`，应用不自动追加 `/v1`，只追加 `audio/transcriptions`、`chat/completions` 或 `messages`。Anthropic Messages 不作为录音转写接口。仅支持 HTTPS；Key 经 Android Keystore 加密后保存，不写入日志。连接测试发送固定测试语音或虚构文字，会实际调用所填服务并可能计费。

优先使用授权目录中的系统录音。文件名同时含可唯一对应的号码和 `yyyyMMdd_HHmmss` 或 `yyyyMMdd-HHmmss` 时间时，后台尝试关联来电；其它命名通过通话详情手动选择关联，避免误配。也可以从系统文件选择器导入录音。应用保存私有副本，删除归档保留系统原文件，并阻止后台再次自动导入同一次通话。

录音与来电统计使用独立开关和来电登记。开启录音后，对系统交付且能取得号码的来电独立留档；关闭统计仍可采集、导入和分析，录音记录不会增加统计次数、扣分或报表明细。关闭录音也不停止原统计。已有录音与删除标记会保留；旧统计归档兼容读取，原报表可通过可选关联打开对应录音。

系统没有可用录音时，可选择“实验性麦克风”并授权麦克风，接听后尝试通过带通知的前台服务采集。Android 对双向通话音频有系统限制，该路径可能仅有本机声音、静音或被系统拒绝；应用将其标为未经验证，不承诺听筒或蓝牙下可以录到双方。挂断、通知中停止或关闭录音开关后停止采集。检测为静音的音频不会提交分析成功结果。

在“档案 → 通话录音”独立查看录音列表，导入、回听、分析/重试或删除；“号码报表 → 逐次明细 → 录音与分析”仍提供关联入口。录音转为 16 kHz 单声道 WAV，以五分钟为单位分段转写；长转写分段分析后合并，超出两小时音频、256 MiB 导入或 256,000 字符转写上限时明确失败，不静默截断。重试复用已完成的转写；临时网络错误有限退避重试，Android 停止后台任务后可恢复，删除会取消后续上传和丢弃迟到结果。

归档保存转写、自述姓名/单位/职位、原文依据、模型推测、1–3 句话摘要及待办。身份推测不等于真实身份核验；确认后可将自述姓名和单位写入档案，职位和白名单不自动修改。AI 失败不影响原有来电筛选、铃声、统计与报表。

本轮自动测试验证本地业务、协议与界面；未使用真实付费 API。目标小米设备 ADB 离线，系统录音目录适配、真实 SIM 双向采集、听筒/免提/蓝牙与锁屏后台采集尚未实测，不能据此宣称两条录音路径均已通过验收。

## 权限与后台边界

| 条件 | 用途与缺失时的表现 |
| --- | --- |
| 来电识别角色 | 系统交付可筛选来电，不更换默认拨号器 |
| 电话状态、通知 | 播放与通话结束管理、前台服务通知 |
| 通话记录 | 补全结果与时长；未授权保留可登记事件及未知时长 |
| 通讯录（可选） | 让系统交付已保存联系人的来电；缺失时无法保证这些来电的悬浮窗和免打扰 |
| 显示在其他应用上层 | 显示来电卡片；缺失不妨碍编辑、统计和免打扰 |
| 后台运行、自启动与电池设置 | 在手机应用设置检查，厂商省电策略可能限制后台入口 |

核心来电处理不依赖页面、亮屏或联网。息屏不主动点亮屏幕；通话结束与系统记录变化安排后台补全，系统延后执行时保留待补全状态。重启恢复从首次解锁后开始；强行停止、撤销权限或角色后需要重新打开应用并恢复条件。覆盖安装后也应重新检查权限。

规则铃声准备保留 1.8 秒期限和失败放行；接听、挂断、权限撤销或看门狗结束服务。系统已接受静音响应后，若播放进程被杀，接口无法重新打开原系统铃声。

## 架构与构建

`app` 负责 Application 组装、平台业务适配与来电入口；`ui` 负责 Compose 页面、MVVM 状态、统一主题、悬浮窗和 Glance；`backend` 提供业务 API 与业务计算。`CallringApplication` 创建单个业务图，生产 UI 注入正式 `CallringUiApi`，Fake 仅位于测试源集。普通 Screen 接收状态与回调；阻塞工作由可从主线程调用的 API 实现调度。旧生产 UI 与旧业务副本已移除。

工具链：**JDK 17、Gradle 8.13、AGP 8.13.2、Kotlin/Compose compiler plugin 2.3.21、Compose BOM 2025.12.01**。Java/Kotlin JVM 目标为 1.8；minSdk 29、compileSdk 36、targetSdk 33、Build Tools 36.0.0。通过 `local.properties` 或 `ANDROID_HOME` / `ANDROID_SDK_ROOT` 配置 SDK；JDK 使用当前环境的 `JAVA_HOME`。

版本只在根 `version.properties`（`versionCode`/`versionName`）维护：根 `build.gradle` 校验后注入 `app/build.gradle`，发布工具读同一文件，标签统一为 `v<versionName>`（当前 `0.3.0` / `versionCode 3`）。改版本请用 `python tools/release/version_tool.py set --code N --name X.Y.Z --published-max M`，脚本会拒绝 `0.3`、`v0.3.0`、非递增 versionCode 等输入。

统一验证入口（`backend` 是 `java-library`，测试任务为 `:backend:test`）：

```powershell
python tools/verify_backend.py
python tools/verify_ui.py
.\gradlew.bat :backend:test :ui:testDebugUnitTest :app:testDebugUnitTest :app:assembleDebug :ui:lintDebug :app:lintDebug
```

Debug 构建生成 `app/build/outputs/apk/debug/app-debug.apk`；Release 构建生成 `app/build/outputs/apk/release/app-release.apk`。UI 验证另运行 `:ui:assembleDebugAndroidTest`，日志和带计数的结果写入忽略目录 `ui/build/qa/`。

签名：`app/build.gradle` 的 `signingConfigs.release` 优先读取被 gitignore 的根 `signing.properties`（`storeFile`/`storePassword`/`keyAlias`/`keyPassword`），文件缺失时回退本机 Android debug keystore。**当前发行身份是本机 debug 证书**（证书 SHA-256 `5a901cad…24b4`）；v0.2 正式包的发行密钥已丢失，任何构建都无法覆盖 v0.2 安装。覆盖升级要求同包名、同签名且 versionCode 递增。`backendQa` 变体沿用 debug 签名并带 `.backendqa` / `-backend-qa` 后缀，不得作为正式包发布。

本地发布校验（生成元数据并四者互校，不上传）：

```powershell

python tools/release/generate_release_metadata.py --apk app/build/outputs/apk/release/app-release.apk --out-dir dist
python tools/release/verify_release.py --release-dir dist --tag v0.3.0 --published-max 2 `
    --expected-cert-sha256 5a901cad57f5590483f362e4752ca8f4a56197340b71d2632ded0195bf8a24b4 --check-alignment
python tools/release/selftest.py
```

`.github/workflows/release.yml` 是手动触发的失败即停发布流水线：签名 Secrets（`KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`）缺失时在构建前失败；默认 `publish=false` 只构建与校验，不创建或上传 Release。`.github/workflows/build.yml` 在 push/PR 上运行统一验证与发布工具自检（仓库只含 `gradlew.bat`，CI 通过 Gradle 8.13 直接执行）。

## 隔离设备验证

先手动唤醒并解锁设备，确认 ADB 在线：

```powershell
python tools/verify_ui.py --device ADB_SERIAL
python tools/verify_backend.py --device ADB_SERIAL
```

UI 脚本核对元数据与 APK 包名，只安装 `com.greatwall.callring.ui.test`，使用 `UiTestRunner` 执行 `com.greatwall.callring.ui` 下的测试；不会覆盖生产包或 `com.greatwall.callring.backendqa`。它等待安装安全扫描完成，临时允许测试包悬浮窗权限，并在 MIUI/HyperOS 临时允许测试包 app-op `10021`，最后恢复原模式。设备命令有超时，退出时仅停止 UI 测试包；不更改锁屏超时、不自动解锁、不清除应用数据。Backend QA 使用独立的 `com.greatwall.callring.backendqa` 包，按其脚本维护的测试范围运行。

构建、单元测试和隔离设备测试不能替代真实来电验收。当前迁移验证依据与未完成项目统一记录在 [UI 重构验收](docs/plans/UI重构_验收.md)：实际悬浮窗显示、重挂载、编辑草稿和桌面双组件已有隔离实机证据；键盘遮挡、系统锁屏、真实 SIM、30 分钟息屏及重启后恢复仍需现场验收。旧实现的历史验证记录不作为新 UI 的最终通过依据。
