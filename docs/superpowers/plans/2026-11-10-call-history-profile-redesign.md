# 通话记录与号码档案详情重新设计实施计划

> 执行时使用 executing-plans 或 subagent-driven-development，按阶段验证。复选框用于跟踪实施进度。

**目标**：调整通话记录列表，重组号码报表为可展开的号码档案详情页，并精简单次通话详情。

**架构**：保留现有 Compose/MVVM、正式档案编辑命令和通话详情入口。通话列表与号码详情复用同一通话行及播放、转写能力。后端按页投影档案摘要和指定号码的可见通话，报表统计继续使用现有区间查询。

**技术栈**：Android、Kotlin、Compose Material 3、SQLite、JVM 和隔离设备测试。

**实施基线**：从包含统一通话记录的 `596fbeedfc10a838262fae5174a6cd046aa4234d` 或其后续已核对提交开始实施。开工前获取最新 `origin/main`，确认基线包含 `CallHistory.kt`、`CallHistoryService.kt` 和 `CallHistoryScreen.kt`，并核对计划与当前代码的差异。项目主目录当前的 detached HEAD `95b4328` 不包含上述文件；保留该目录已有改动，在包含基线的合适工作树中实施。

## 交互与数据约定

- 全局「通话记录」每行显示档案摘要、日期时间、录音和转写图标。摘要依次拼接姓名、地区、职务，姓名为空时以号码替代，其他空项省略。姓名和号码作为主文字，字体大于日期时间。日期时间使用通话事实保存的时区，工作时间内为低饱和绿色，工作时间外为低饱和红色，移除原圆点。工作状态未知时使用中性色，并提供无障碍说明，避免将未知事实显示为工作时间外。
- 职务摘要优先使用已有的「自述职位」文本，缺失时使用已配置的职位名称，均缺失则省略。此选择仅用于展示，两个字段的存储和编辑语义保持独立。姓名、地区和职务之间使用间隔分隔，长文本单行省略，字号缩放时日期和两个图标仍可触达。
- 录音图标继续播放或停止，转写图标继续打开全文弹窗。缺内容、索引准备中和读取失败使用现有不可操作及错误状态。点击图标只执行对应操作，点击行其余区域进入相同的单次通话详情。
- 「号码报表」入口进入标题为「号码档案详情」的页面。号码信息、报表信息、通话记录三个标题各有右对齐的展开或收起按钮。初始均收起，返回详情时保留当前展开与滚动状态，配置变更和进程重建按现有保存状态机制恢复。
- 号码信息收起时展示同一套姓名或号码、地区、职务摘要。展开后展示号码、姓名、部门、自述职位、所属地区、职位级别、上下级关系、白名单及已有字段来源和异议状态。当前可编辑字段旁显示编辑图标，点击后进入该字段的编辑交互。号码和计算所得上下级关系按现有契约展示，只有正式编辑入口支持的字段可编辑。
- 报表信息收起时展示当前选定区间的来电总数和现有评分，评分缺失显示「未知」。展开后保留现有日期区间、全部统计、质量提示、权限入口、筛选和 CSV 导出，说明筛选只影响报表明细的原有语义。默认区间与现有页面一致。
- 号码详情中的通话记录独立于报表日期和分类筛选，展示该号码所有应用内可见来电。首次以固定页大小 50 加载，收起时只渲染首屏的最新三条；展开后展示已加载的首屏并沿用其游标继续加载，整个分页链保持页大小不变。行只显示日期时间和与全局列表相同的录音、转写图标，行本身进入单次详情。没有更多记录时不显示加载按钮，合并记录只出现一行。
- 整页使用一个纵向滚动容器。号码信息区域离开可视范围后，顶部标题显示相同的档案摘要，返回可视范围后恢复「号码档案详情」。展开按钮具有明确的状态和无障碍名称，长标题截断且不遮挡返回按钮。
- 单次通话详情整合号码、时间、时长、分类、结果、录音及转写状态。删除重复说明和静态操作提示，将导入入口、分析结果及确认操作组织为清晰分组。保留缺失、失败、重试、取消、来源依据、分析费用提示及删除确认等会影响操作判断的信息。独立录音归档继续可用。

## 执行补充

- 配置职位名称来自职位表。正式职位命令通过 `CALLERS` 和 `REPORTS` 发布受影响号码，列表、游标和档案区域沿用这些依赖；单纯新增或修改未被引用的职位不会触发重读。验证只改所引用的职位名称也会更新全局行、号码摘要和滚动标题。
- 号码通话页按号码订阅通话和档案。录音归档仍沿用现有的归档 ID 和通话关联失效协议，号码页使用归档域 token 以接收尚未投影的新关联，其他号码的归档写入也可能触发刷新。
- 列表失效时从首屏开始，按原已加载页数重建分页链，使用通话 ID 和行内偏移恢复位置。锚点已删除或超出重建范围时回到通话列表首屏。号码详情按路由保存展开状态与滚动锚点，并保存恢复锚点所需页数。收起时仍只渲染前三条，重新展开复用当前页链。
- 窄屏和大字号下优先保证日期与两个图标可读可触达，允许日期换行，摘要保持单行省略。
- 在独立功能分支执行。隔离设备优先使用模拟器，验证前确认测试安装包身份。按阶段记录实际通过的验证，再更新对应复选框。

## 分页索引验证

在本机 SQLite 3.40.1 的内存数据库执行生产分页的列投影和关联查询。夹具包含两个号码、24 万条通话和大量相同时间戳，目标号码的 1,200 条可见通话间隔分布在隐藏记录中。两组索引都通过逐页比对完整排序 ID，未出现重复、漏行或隐藏记录。每次查 51 条，保留第 51 条判断是否有下一页。

| 范围 | 原索引的 SQLite 虚拟机指令 | 可见号码索引的 SQLite 虚拟机指令 |
| --- | ---: | ---: |
| 首页 | 28,571 | 3,223 |
| 同一时间戳且 ID 较小，两种游标深度 | 28,081 | 3,229 |
| 更早时间，两种游标深度 | 28,574 | 3,226 |

旧索引集合下查询使用 `calls_number_time`，同时间戳以 rowid 定位；`calls_visible_time` 未被选中。新计划使用 `calls_visible_number_time(number,time DESC,id DESC) WHERE hidden=0`，首页按号码定位，后续查询分别按号码、时间、ID 或号码、较早时间定位。两组查询均未使用排序临时 B-tree，关联的筛选事实均按整数主键查找。启用指令计数时，单次样本耗时由 4.77–6.97 ms 降至 0.68–0.77 ms。24 万条单事务写入取三轮中位数，隐藏记录为主时约 795→842 ms，全部可见时约 978→1,055 ms。这组数据用于比较内存数据库中的访问工作量。

## 验收判定

全局通话行按档案摘要、日期和图标展示，工作时间颜色与历史事实一致。号码详情默认展示三个收起区域、三条最新通话，展开后可编辑档案、查看完整报表和分页浏览全部通话。滚动标题与档案实时一致。两处通话图标和行导航独立，单次详情保留完整业务操作与必要反馈。查询、刷新、并发、无障碍和设备验证均有对应证据。
