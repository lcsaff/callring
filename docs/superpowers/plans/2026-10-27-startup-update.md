# 启动检查更新实现计划

**目标：** 启动主界面时自动检查一次；新版本使用通用可关闭弹窗提示，确定进入更新页。

**设计：** UI 应用级 StartupUpdateViewModel 在首次启动调用现有 AppUpdateApi，随宿主保留，不因重组、旋转、页面切换或恢复前台重复检查。失败和无更新静默；下载、校验及待安装状态不主动重新检查。复用 designsystem 的 ConfirmationDialog，增加可配置关闭文案；组件只接展示参数及回调，不包含更新业务。网络迟到结果不得覆盖后续检查或下载状态，不增加契约、偏好或订阅。

**实施与验收：**

- [x] 先添加启动检查、关闭与确认导航测试，运行确认现状失败。
- [x] 添加启动 ViewModel 和根界面接线，复用通用弹窗，更新页面说明。
- [x] 添加平台并发回归测试，阻止旧检查结果覆盖新状态。
- [x] 验证启动只检查一次、无更新/错误静默、关闭不重复弹出、确认进入更新页、下载/安装仅手动触发。
- [ ] 同步 PROJECT.md 和 README.md，审查差异，运行统一验证门。
- [ ] 按项目交付规范提交、合入 main、推送并确认该提交 CI；无设备时注明设备验证未执行。

定向 JVM 测试覆盖界面状态恢复、已打开更新页在检查结束后的刷新、INSTALL_PENDING_VERIFY 跳过检查、取消后的迟到 UI 响应、旧检查不能覆盖新检查与已校验下载。新增回归均先观察失败再修复；独立审查的两项 P2 均已修复并复审。完整门和 CI 的最终证据以对应提交构建目录和远端记录为准；本机 ADB 无在线设备，未执行真机启动/旋转或真实网络安装验证。
