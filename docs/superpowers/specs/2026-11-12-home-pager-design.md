# 四页主页 Pager 设计

日期：2026-11-12。状态：待用户审阅，尚未实施。

## 目标与范围

按本次六项要求，将首页、档案、沟通、设置放进一个 HorizontalPager。详情、编辑、设置子页、录音及其他次级目的地继续使用现有 NavHost。保留窄屏底栏、宽屏导航栏和键盘出现时隐藏窄屏底栏的行为。

功能归 ui/app 的导航容器和 ui/feature 的页面状态，不新增后端查询、存储格式、AI 工具或失效域。查询与修改仍走 CallringUiApi；刷新仍走 ChangeFeed.snapshots()、ObservedQuery / SnapshotViewModel 和 TimeRefresh 的现有协议。

## 现状核对

- CallringApp.kt 将四个主页分别注册为导航目的地，通过 navigate、saveState 和 restoreState 切页。
- HomeViewModel、CallerListViewModel、ConversationViewModel 在各自导航目的地创建；设置摘要 SettingsSummaryViewModel 在应用层创建并立即订阅加载。
- CallerListViewModel 的 SavedStateHandle 已保存搜索文字和页码；其领域失效会将分页重置到第一页，这是现有刷新语义。
- 首页和设置使用 rememberScrollState，档案使用默认 LazyColumn 状态，沟通使用 rememberLazyListState；需要稳定的 SaveableStateHolder 键维持移出组合后的恢复。
- 沟通草稿目前使用进程级 MutableStateFlow，进程退出后丢失。沟通的 readingHistory 是普通 remember 状态，重新组合后可能自动跳到最新消息。
- 会话业务状态和正式请求由 api.conversation 提供。切页不得发送 stop 或 newSession，也不能把发送任务绑到 Pager 页面的组合协程。
- 主页内有免打扰编辑弹窗、新对话确认，应用层有启动更新提示及 AI 前台交互弹窗；这些都需要阻止背景切页。
- 检查时 ADB 设备列表为空，设备验收尚无可用目标。原工作区已有其他文档和临时文件改动，须原样保留，提交只选择本任务文件。

## 方案比较与选择

| 方案 | 代价与效果 |
| --- | --- |
| 单一主页导航目的地 + HorizontalPager + 稳定页面状态宿主（推荐） | 统一切页状态；按访问创建页面模型；预合成与查询分离；次级页面复用原导航。 |
| 四个 NavHost 目的地保留，再用手势触发 navigate | 出现手势目标、导航路由和动画三份切页状态，不能自然满足 HorizontalPager 容器要求。 |
| Pager 预先创建并常驻四个完整页面 | 实现较直接，但启动触发额外查询和订阅，违反首次进入才加载的要求。 |

采用第一个方案。只拆分与本次功能直接相关的主页宿主及手势协调，其他页面不作通用重构。

## 导航与切页状态

1. 保留 home 作为根导航目的地，根内容改为四页 Pager；四个主页不再各自维护一条 NavHost 返回栈。UiDestination 的外部目标名称保持兼容，进入主页目标时映射到对应页索引。
2. PagerState 是运行期间页签与滑动的共同来源，不再双向同步第二份 selectedTab。保存稳定页索引用于恢复，不保存半途拖动位置。
3. 固定四页和稳定键 home / callers / conversation / settings，不循环。原生横向拖动判定和单页吸附限制一次滑动最多前进或后退一页。
4. 点击页签直接切到目标页，快速点击时最后一次选择生效；直接跳转不让跨过的中间页面变成一次实际访问或触发加载。
5. 仅根主页可见时启用主页返回逻辑：非首页返回首页，首页保留宿主原有退出行为。次级目的地先按原栈返回到来源页；弹窗先关闭，键盘和文本选择按系统规则优先处理。
6. 打开详情、编辑或设置子页不覆盖当前主页页索引。通知目标沿用 UiNavigationState.consume 的一次性处理，恢复时不重复覆盖已保存选择。

## 页面状态与任务所有权

- 将已访问页面的 ViewModel 保存在稳定主页宿主的 ViewModelStore，使用明确的页面键和独立 SavedStateHandle；页面移出组合不销毁模型，旋转也不重建业务任务。
- 页面 UI 使用稳定键的 SaveableStateHolder；滚动状态和沟通 readingHistory 使用可保存状态。滚动恢复不应因 AI 后台新增消息而把用户从历史位置拉到底部。
- 档案复用现有搜索及页码保存，不复制一套过滤状态。实际相关领域失效仍按原协议重置页码并重查；单纯切页或短暂详情返回不重查。
- 草稿改为宿主拥有、经 SavedStateHandle 保存的 UI 输入，删除最后消费者迁出后的进程级草稿全局变量。旋转、切页及系统保存状态后的进程恢复均恢复草稿。
- 草稿恢复不代表恢复聊天历史、业务请求或执行 AI 操作。进程内切页时请求继续；进程终止后沿用现有会话终止语义，不自动重放发送、续办或已提交修改。备份不加入聊天内容。
- 发送成功清空输入时继续使用原有比较保护，不能覆盖发送后新编辑的草稿；失败保留输入和错误。
- 离开页面时清理焦点及相应输入会话，避免隐藏页面继续持有键盘；保留文本本身。

## 首次加载与生命周期

- Pager 可以预合成相邻页的外壳，但首次业务模型创建和订阅只由实际选择或滑动完成后的可见页触发。未访问相邻页不运行 loader，不调用检查连接或其他业务操作。
- 已访问页面的模型继续使用现有累计失效观察。页切换本身不是刷新事件，不对所有已访问页广播 refresh。
- 设置摘要不再因为 CallringApp 首次组合就无条件创建；只有设置主页或确实依赖摘要的现有子页首次使用才获取，并共享同一实例。外观主题和启动更新仍按各自现有应用级职责初始化。
- 首页 TimeRefresh 只对当前可见主页运行；返回后由保留的 schedule 判定是否跨过时间边界、时区或恢复信号，避免短暂切页重复查询。
- 次级目的地的 TimeRefresh 和生命周期清理保留原语义；页面不可见与应用进入后台分开处理，不把预合成当作恢复前台。
- 保留 RefreshCoordinator 的在途去重、迟到结果隔离及错误保留。新增容器不实现第二个查询缓存或 loader。

## 手势协调

- 普通区域由 Pager 和纵向滚动组件按触摸阈值、主方向及事件消费协调；不在父层抢占全部 pointer down，也不把普通竖向拖动转成切页。
- 为输入框、文本选择和横向可滚动区域提供局部手势保护边界。一次手势若起点属于这些区域，整个手势由该区域处理，达到自身边界也不接力切页；避免只按当前焦点全局禁用所有滑动。
- 长按复制成立后阻止同一手势继续切页；保持现有链接点击、长按复制、辅助功能动作及震动反馈。
- 两侧系统返回手势区域的起点让给系统，按宿主提供的系统手势 inset 判断，不使用全屏排除区；中间内容区域仍可正常切页。
- 显示免打扰编辑、新对话确认、启动更新或 AI 前台交互弹窗时禁用 Pager 用户滚动及背景页签切换。若拖动中打开弹窗，取消本次拖动并稳定在已确认页，关闭后恢复。
- 手势保护只提供交互信息，不将业务 API、Context 或 Activity 引入 designsystem。

## 验证矩阵

| 场景 | 必须观察的结果 |
| --- | --- |
| 冷启动首页、相邻页预合成 | 首页各正式 loader 仅首次加载；档案搜索、沟通设置及设置摘要计数为零。 |
| 点击远端页签、快速交替点击 | 最终页、选中页签一致；中间页未访问时查询为零；无重复会话发送。 |
| 高速 fling、反向拖动、两端外拖 | 一次最多一页；两端不循环；取消拖动不改变已稳定选择。 |
| 纵向滚动及斜向拖动 | 按主方向处理；正常阅读列表不误切页。 |
| 搜索、分页、长列表切走再返回 | 文字、页码、滚动位置保留；无失效时 loader 增量为零。 |
| 打开详情或编辑后返回 | 回来源页并复用状态；正式相关失效按原协议刷新，无关 loader 增量为零。 |
| 草稿编辑、光标横移、文本选择 | 草稿保留；输入及选择手势不触发切页。 |
| AI 延迟回复期间切页及打开详情 | 正式发送仅一次；后台正常完成；回来显示结果，阅读历史位置不丢。 |
| 横向控件、长按复制、系统边缘返回 | 各自处理手势；返回先回主页首页或按次级导航退栈。 |
| 弹窗在拖动中或静止时出现 | 背景 Pager 和页签不切换，关闭后恢复，确认动作不重复。 |
| 横竖屏、窄宽窗口切换、键盘 | 保留所选页、各页滚动和草稿；导航形态变化不额外查询；输入区可见。 |
| 保存状态恢复、隔离宿主进程终止重建 | 恢复页签、搜索分页及草稿；业务数据按新进程首次读取；不自动恢复旧 AI 执行。 |
| 相关、无关及累计领域变化 | 真实 loader 计数符合订阅；不以全局刷新掩盖漏订阅。 |

先增加有意义的失败回归，再实施并验证。JVM Compose 测试覆盖导航、计数、状态恢复及交互；隔离设备补实际拖动、IME、旋转、系统返回和宿主恢复。SavedState 模拟恢复不冒充真实进程恢复，模型延迟 Fake 不冒充真实付费 AI 服务。
