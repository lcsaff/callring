# 通话录音与 AI 分析设计

日期：2026-10-18。状态：需求已确认，书面设计待用户审阅。

## 已确认需求

- 系统电话有录音时直接使用；无系统录音时研究并验证其他录音路径。
- 对本次通话分析对方身份，简明总结内容并关联留档。
- 只支持 OpenAI、Anthropic 兼容 API；用户选择兼容接口类型，配置 URL、API Key、Model。兼容指协议，不限制实际服务商，不固定模型列表。
- 目标设备已有记录：小米 15 Pro（2410DPN6CC），Android 16，HyperOS OS3.0.308.0.WOBCNXM。来源：docs/plans/来电管理扩展_验证.md。当前 ADB 离线，尚未验证录音获取。

## 推荐方案与范围

采用录音、转写、文本分析三段式流程。相比分别维护服务商专属 SDK，兼容协议适配更符合用户指定的配置方式；相比端侧模型，本轮不需要下载和维护模型。

首版按通话结束后处理设计。录音来源独立于 AI，失败时保留记录和可重试状态。实时身份提示需要通话中连续取得音频，不包含在当前首版方案中。

## AI 配置及协议

设置增加“通话录音与 AI”。包含独立的录音开关、自动分析开关和两组连接配置：

1. 内容分析：接口类型为 OpenAI 兼容或 Anthropic 兼容；字段为 URL、API Key、Model。
2. 录音转写：接口为 OpenAI 兼容音频转写；字段为 URL、API Key、Model，可提供复制内容分析连接参数的动作，但保存后两组参数独立。

URL 定义为 API 基础地址，包含服务商要求的版本路径。例如 https://example.com/v1。保留自定义前缀，去除末尾斜线后追加 chat/completions、messages 或 audio/transcriptions；不猜测或替换版本路径。

OpenAI 内容分析使用 POST chat/completions 和 Bearer 认证。Anthropic 使用 POST messages、x-api-key、anthropic-version，system 放在顶层，显式传 max_tokens。首版使用非流式请求，分别解析 choices[].message.content 与 content[] 文本块。不要求第三方实现专有结构化输出扩展；通过提示词要求 JSON，并在本地校验字段。

转写使用 POST audio/transcriptions，multipart 上传 file 和 model，解析 text。聊天模型不能自动当作转写模型，Anthropic Messages 不作为转写接口。只配置分析服务时可保存配置，但自动录音分析提示转写配置缺失，不发送不兼容音频请求。

每组提供独立连接测试，分析测试使用固定无个人信息文本；转写测试使用随应用提供的短测试语音。明确提示测试会调用配置服务、可能产生费用。失败分别显示地址、认证、模型或接口不支持等原因，不能只测试 models 列表后判定可用。

API Key 使用 Android Keystore 密钥加密后保存；界面默认遮挡，不在日志、报表和错误消息中输出。通过 HTTPS 调用，不把凭据转发到跨域重定向目标。模型名自由输入，不自动升级或替换。

## 录音获取及能力验证

优先使用系统录音，通过用户授予的文件访问能力读取；支持主动导入、手动关联本次通话，避免依赖特定私有目录。仅在号码、时间及录音元数据能唯一匹配时自动关联，歧义时让用户选择。

无系统录音时，先在目标设备探测可用采集能力，验证系统授权、后台启动、双向可听性及听筒/免提/蓝牙路径，再选择适配实现。普通麦克风权限不代表可获取双向通话；默认拨号器角色也不能替代系统音频捕获特权。

录音适配接口返回可用性、来源、开始/结束结果与失败原因。采集到静音、单侧音频或无法确定有效性时必须如实标记，不能仅凭文件存在就显示“双向录音成功”。无法录音时保留缺少音频状态，允许以后补导入；这不是满足“无系统录音也能录”的验收证据。

本轮不自动 root、不修改系统分区或系统电话应用。若实测只有新增系统权限或设备改造才可实现，先说明具体证据与方案，再决定该路径；不能以导入功能替代未完成的录音目标。

## 数据、分析及留档

按现有来电 ID 关联录音附件、转写、分析结果；号码相同不能作为唯一关联依据。附件记录来源、时长和音频质量状态。结果保存服务类型、模型、处理时间与输入版本，便于重试和判断过期结果。

分析返回对方自述姓名、单位、职位、来电目的、原文依据、推测身份、1–3 句摘要及待办。信息不足字段留空，区分自述与推测，不把 AI 结果当作真实身份核验，不自动覆盖档案。用户确认后才更新档案。

通话内容只作为待分析数据，不能作为模型指令执行，不开放工具调用。对模型 JSON 做大小、类型及字段校验；不合格结果显示分析失败，不直接写入档案。

本地保留录音、转写、摘要，可回听、重试和删除应用内附件。删除归档取消相关任务；晚到响应不能恢复已删除数据。删除应用副本不删除系统原录音。长音频按转写服务限制分段，超出模型上下文时分段提炼再汇总，不能静默截断。

默认录音和自动上传开关关闭；用户开启自动分析后，向所配置转写服务发送音频，向分析服务发送转写及必要的已确认档案信息，不上传全部通讯录。更新 README 中现有“仅联网下载节假日”的说明。

## 模块与任务状态

- backend：配置、录音关联规则、分析归档模型、任务状态、UI API。
- app：系统录音读取、设备采集适配、音频处理、Keystore、HTTP 协议实现、持久后台任务。
- ui：设置配置、能力及任务状态、通话详情的录音/转写/身份/摘要、导入关联与重试。

状态区分等待录音、待转写、转写中、待分析、分析中、完成、失败与取消。任务和输入版本持久化，重启可恢复；并发重试防重复落库。网络失败、限流、服务端临时错误有限退避重试；认证和配置错误等待用户修正。AI 处理不得阻塞现有来电筛选与铃声期限。

## 验证与完成标准

单元测试覆盖两种协议请求/响应、地址拼接、密钥隐藏、转写接口区别、无效 JSON、身份依据、录音唯一关联、重试去重、删除与晚到响应竞争及配置持久化。实际 HTTP 测试通过本地模拟服务，不需真实 Key。

运行 backend/app/ui 对应单元测试、构建与 lint，保留现有工作时间、铃声、报表回归。使用用户配置的实际兼容服务验证转写和分析后才能标记联网链路已验证。

实机分别验收系统录音可用与不可用两条路径、真实 SIM 双向音频、听筒/免提/蓝牙、后台/锁屏及进程恢复。设备离线、缺少服务配置或只有模拟测试时，如实记录未验证项；双向采集未通过前不得宣称整个录音需求完成。
