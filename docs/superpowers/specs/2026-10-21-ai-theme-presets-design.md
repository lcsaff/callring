# AI 无法识别三个主题色预设：修复方案

## 问题与证据

用户在沟通中要求将主题色改成联通红，AI 回复系统没有该预设。当前 UI 的 ThemeRegistry.Default 定义了 unicom_red（联通红，#E60012）、sky_blue 和 teal_green，但 AI 的 settings_getAppearance / D11 查询仅返回已保存的外观字段，settings_saveAppearance 工具说明也没有可选预设目录。

缺失的是 AI 可见的预设元数据；尚未复现用户当次模型调用，不把模型的拒绝等同于保存 API 失败。

用户确认修复范围包括联通红、天空蓝、青绿色，三个预设一并接入共享目录和回归验证。

## 方案选择

推荐将内置预设的 id、显示名、RGB 元数据放入 contracts，UI 从该目录生成调色板，AI 从该目录获得可选项。另一方案是在工具描述中手写名称映射，改动较少，但会保留两份定义，后续易失配，因此不采用。

## 修复范围

- contracts 维护唯一内置预设元数据，不引入 Compose 或 Android 依赖；调色板计算保留在 ui。
- UI 保持既有预设、颜色、顺序、自定义颜色及未知预设回退行为。
- D11 外观查询在保留现有字段的基础上，附加只读 presets 列表，包含 id、name、seedRgb。settings_getAppearance 复用该源投影。
- 外观读写工具描述引用共享目录，明确切换联通红应提交 selection=PRESET、presetId=unicom_red；仅改主题时保留深浅模式。
- 写入继续使用既有外观业务入口、并发校验、失效发布和读回验证；不新增业务写入入口。

## 数据、订阅与协议

不更改持久化格式，不迁移或覆盖用户设置，不增加业务订阅。D11 新增 presets 为只读协议字段；审查受影响的协议断言，仅有依据地调整对应预期，不批量重生成基线。

## 验收

1. 先增加失败测试，证明 AI 外观读取与工具发现缺少联通红映射。
2. 修复后，真实查询链路可读到联通红的准确标识与 RGB，并与 UI 目录一致。
3. 使用既有工具执行链从其他颜色切换到联通红，读回预设成功且深浅模式不变；有关外观更新正常，无关查询无额外读取。
4. 运行受影响 JVM 测试、架构守卫与项目统一验证入口 python tools/verify_backend.py。
5. 如未进行真实模型或设备验证，明确列为未验证，不以单测代替。保留已有用户改动。

## 交付

通过验证后，按项目规则审查变更、提交并推送 main，确认对应 CI。此次修复不默认安装到用户设备或发布 APK；需要分发版本时再按发行规则递增版本。
