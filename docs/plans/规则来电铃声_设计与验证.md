用户已确认采用“匹配来电静音 + 自行播放音频”，要求与现有 App 分开并在已连接手机试用。

2026-10-14：项目已从 android-funs 拆至用户指定的 `D:/Users/GreatWall/projects/callring`，应用模块改为 `app/`，独立维护 Gradle 构建入口。下列实现与设备验证记录对应 2026-09-19。

## 设计

- 新建 `callring` Android application 模块，包名 `com.greatwall.callring`，名称“规则来电铃声”，独立图标、数据、APK；已有 `app` 模块保持原样。
- 沿用本地 Gradle 7.5 / AGP 7.3.1 / SDK 33，minSdk 29、targetSdk 33。这是 Android 16 实机验证用的侧载原型，不代表以 targetSdk 36 验证。
- 用户启用规则后，仅处理来电且号码严格匹配 `^3[0-9]{4}$`。隐藏号码、外拨、未匹配、静音/振动、勿扰、正在通话、电话状态权限不足时直接放行。
- CallScreeningService 使用 1.8 秒绝对准备期限。播放服务先进入 mediaPlayback 前台服务、准备本地音频，再回报就绪；筛选服务在同一主线程同步预留有效会话后放行并设置 silenceCall。准备失败、取消或超时则保留原系统铃声。
- 播放服务通过公开 TelephonyManager 聚合通话状态等待 ringing，才播放铃声；结合 AudioManager 音频模式检查活跃通话，避免通话等待覆盖活跃状态。接听/拒接/挂断/用户停止时释放播放器；未进入响铃 4 秒及最长 90 秒看门狗停止。来电复用 Telecom 的音频焦点，试听才自行申请并在失焦时停止。准备后发生系统异常无法保证恢复原铃声。
- 单个播放会话有唯一 token，过期的提交/取消不能影响新会话。已有会话时不替换，不将另一通来电静音。
- 使用来电铃声音频属性，遵守系统铃声音量，不修改全局铃声或音量。内置短旋律；可用系统文件选择器导入音频至本 App 私有文件，限制 20 MB。
- 主界面：权限与角色状态、规则开关、音频选择/恢复内置、试听/停止、规则样例检查、脱敏最近事件。
- 不申请通讯录权限，故已存联系人来电暂不覆盖；不申请通话记录、网络或默认拨号器角色。
