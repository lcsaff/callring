## 约束更新

为以编译边界保证分离，API、领域规则和应用服务提升到纯 JVM `backend` 模块；Android SQLite、文件、系统权限和播放适配保留在 `app`。API 包名和 v1 签名保持不变。该变更取代实施计划中“只用 app 内包边界”的物理部署选择，业务任务和数据保留要求继续适用。

后端不能引用 Android、Compose、Glance、UI 包、具体 UI 类或展示资源。业务错误使用稳定代码，中文文案和评分色彩由 UI 转换。原数据库中的中文分类值仅在持久化编码边界处理。

## 当前接线合同

生产 Application 由 UI 方实现 `com.greatwall.callring.bootstrap.BackendProvider`，持有单个懒创建 `BackendGraph`。构造参数为 application context、`BackendConfiguration`、`UiNotificationEntryPoints` 和 v1 `IncomingCallUiSink`。UI 只接收 `graph.api: CallringUiApi`，不直接获取存储或业务实现。

`BackendConfiguration` 的 `defaultAppearance` 必填，其余提供正式默认：`databaseName="callring.db"`、`ringPreferencesName="ring_settings"`、`widgetPreferencesName="caller_widgets"`、`appearancePreferencesName="callring_appearance"`。`audioDirectory`、`clock`、`dispatcher` 可用于显式隔离测试。构图和获取 API 不打开数据库或解析音频文件。

`UiNotificationEntryPoints` 由 app 的 UI 宿主适配实现，签名如下；UI 方负责频道、文案、图标、首页路由，业务服务不构造这些展示内容：

```kotlin
fun home(requestCode: Int): android.app.PendingIntent
fun playback(preview: Boolean, stopAction: android.app.PendingIntent): android.app.Notification
```

框架服务通过 `BackendProvider.from(context).backendGraph` 获取图。来电策略、初始记录与最终决策由 `graph.incomingCalls` 串联；落库串行执行，决策执行器独立。`RingPlaybackService` 只保留系统播放生命周期和 PREPARE/READY/COMMIT/CANCEL 握手，实际通知交给上述端口。`RuntimeReceiver` 不调用悬浮窗 UI；通话结束、锁屏等展示生命周期由 UI 自己订阅系统事件处理。

主线程只能读 `AndroidAudioController.enabledForCalls()` 的已提交镜像；`getSettings()`、`configureDataSource()`、诊断落盘在后台执行，避免持久化锁阻塞 Telecom 的 800/1800ms 期限。系统 Job 按 jobId 和运行实例管理停止与重启，不依赖 Binder 重新构造的 JobParameters 对象身份。
