# UI subscription and DTO dependency baseline

Captured before layer migration, 2026-10-20. Domain names below are the current `DataDomain`, not the external D01–D21 source-query domains. This records both declared subscriptions and dependencies of returned DTOs; broad producer notifications can currently hide missing subscriptions. `UiViewModel.observeChanges` delegates to `DataChange.affects`: number filtering applies only to CALLERS/CALLS/REPORTS; null numbers/widget IDs mean unbounded changes. Global domains must still refresh a numbered consumer.

All paths in this document are relative to the repository root. UI classes live under `ui/src/main/kotlin/com/greatwall/callring/ui/`; backend projection classes under `backend/src/main/kotlin/com/greatwall/callring/application/`.

## RefreshIsolationTest coverage and deferred acceptance design

Implemented baseline target: `ui/src/test/kotlin/com/greatwall/callring/ui/state/RefreshIsolationTest.kt`. Three tests use real SnapshotViewModel/UiViewModel/RequestLoader with a replay-free controllable ChangeFeed, coroutine backgroundScope and loader counters. They verify unrelated narrow domains cause no reads; numbered A/B isolation plus null/empty/global-domain semantics; and a recorded all-domain broadcast causes excess loads compared with a narrow event. The broadcast is injected characterization data, not a requirement on future producers. Tests import API declarations only and no backend implementation.

Verification evidence: the parent-run S0 targeted Gradle run completed successfully on 2026-10-20; all three RefreshIsolationTest cases passed. This verifies the baseline loader fixtures, not the deferred screen-DTO or cumulative-feed acceptance cases below.

The following broader acceptance cases remain deferred to the migration. Reuse `sharedTest/.../UiFakeApi.kt` and existing ViewModel constructors for actual screen DTOs; prefer injected counting read adapters over production instrumentation. Assert DTO facts as well as counts so a missing subscription cannot pass because a broad producer happened to emit all domains.

1. Instantiate caller editors A/B and reports A/B with distinct numbers; emit CALLERS(numbers={A}), then POSITIONS(numbers=null). Assert only A reloads first, both reload second, and B's draft is retained. Emit unrelated AI_SETTINGS/APPEARANCE and assert neither editor/report data loader reloads (app theme can reload independently).
2. Change CALL_LOG access via RUNTIME; assert report and overlay **overview quality DTO** refreshes, not merely overlay runtime loader. This should expose the baseline under-subscription until later implementation fixes it.
3. Instantiate home, archive list/detail, AI settings and conversation counters. Emit RECORDING_ARCHIVES for unrelated callId, AI_SETTINGS, RECORDING_SETTINGS and CALLS independently. Assert future intended narrow dependencies; archive and AI settings currently refresh on all events, so capture as migration acceptance, not a claim that baseline passes.
4. Test current widgets i/j through pure WidgetModel/observer seams (Glance-independent): global QUIET_HOURS/WORK_CALENDAR/APPEARANCE reload both; per-number CALLERS/CALLS should cause zero WidgetModel reads after observer narrowing. No binding-based content exists today. A binding-only observer event currently targets IDs and must remain explicitly covered if binding support remains.
5. Exercise two disjoint writes before one consumer resumes; cumulative invalidation must preserve both domains/keys and latest revision. Emit same revision and out-of-order revisions according to agreed future contract. Verify a relevant earlier change is not lost when later unrelated change arrives. This depends on new cumulative feed semantics, so do not encode an invented current interface.
6. Keep lifecycle cancellation/exception behavior explicit. Null-key (all-entities) semantics are included in the baseline fixture. Existing SnapshotViewModel, RequestLoader, widget, overlay and editor tests remain the source for non-regression expectations. The baseline fixture does not claim screen-level acceptance coverage of all rows above or the future cumulative feed contract.
