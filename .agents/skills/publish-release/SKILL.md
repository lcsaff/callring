# 通用 Release 发布

让发布版本、源码、验证证据和发行产物相互对应，并以远端读回证明发布完成。具体规则和命令来自当前项目；发布沿用既定可见范围，不改变访问权限。

## 触发边界

- 仅在用户明确要求发布版本，或继续此前已明确授权的发版时使用；已有授权无需重复确认。既有发布流程可以包含本地构建或 CI 自动公开。
- 普通开发完成、提交合并、单独改版本、编译 Release 变体或仅提供本地安装包，不构成发布授权；不能因为项目有发布脚本或产出安装包就启动本技能。
- 明确发版请求由本技能单独负责全过程，包括发布所需的验证、版本提交、集成与 CI；这些是发版前置步骤，不另行启动普通开发收尾流程。
- 承接已完成的普通收尾时，先核对最终源码与证据；只有仍适用且项目允许的结果才能复用，版本变更后按最终候选重新确认。普通收尾本身不代表已经完成发版。

## 发现约定与范围

- 读取适用的 AGENTS.md 及其指向的项目规范，查找既有版本入口、发布脚本、CI 和发布记录。使用已有工具与认证；CLI 不在 PATH 时先查现有安装，不立即重装或要求重新登录。
- 确认发布平台、目标仓库、分支策略、渠道、版本格式、签名要求与附件清单。不要默认 GitHub、main、SemVer、安装包、三个附件或 Latest；这些参数以项目规范为准。
- 检查工作区、分支、远端及上次发行后的差异。划定发布范围，保留用户未提交的其他改动；必要时用干净检出隔离，不能用全量暂存、清理或重置掩盖混杂状态。
- 用户的发版请求授权其范围内的正常发版步骤，已有授权无需重复确认。不要扩展到未请求的渠道、部署、安装或通知。只有缺失且无法发现的必要信息、凭据或实际审批要求才阻塞依赖步骤，同时继续完成可独立准备的工作。

## 准备版本与说明

1. 查询相关渠道已公开及已分发的版本，包括影响升级或唯一性的版本序号；不能只看本地文件或单个 Latest。沿用项目的 SemVer、CalVer 或其他规则，不自行引入新的版本制度。
2. 通过项目的唯一版本入口及已有工具更新版本，同步必要消费者。已公开或分发的版本不能覆盖重用；尚未分发的候选能否重试由项目规则决定。
3. 发布说明只描述本次实际变化、兼容或迁移影响及重要验证限制，排除凭据、私人日志和原始用户数据。按范围提交，记录候选源码 SHA。

## 验证与产物

- 按仓库要求运行验证门及发布工具自检；设备、平台专项按变更风险补验。证据记录源码 SHA、命令、退出码和未测项，区分本轮执行、有效缓存及未执行；本地通过不代表远端 CI 通过。
- 需要构建时从最终候选构建，需要签名时复用既有签名身份。按实际产物检查版本、包或模块身份、架构、签名、安装或升级约束、必需资源及完整性；不移植其他项目的 SDK、证书或平台检查。
- 需要附件时使用独立暂存目录，冻结待发布文件的名称、大小和 SHA-256；元数据从最终文件生成。校验后若重建、重签或改动文件，重新生成元数据并复核。无需附件的 Release 不强加二进制文件或校验附件。

## 集成与 CI

- 按项目策略提交、合并、推送或触发既有发布流水线，不擅自改变分支策略。
- 合并、冲突解决或补交改变源码 SHA 时，重新确认对应验证和产物；不能把 A 的包挂到 B 的标签，或用另一提交的绿灯代替最终提交。已有证据仅在能证明适用于最终候选且项目允许时复用，无法证明就重跑，不从旧日志推定本轮执行。
- 必需远端检查须核对最终源码 SHA 并等待成功。若由标签触发构建，可按既有流程先创建固定标签；CI 产物须核对其构建来源。流水线会自动公开时，触发前确认其内部已在公开前落实必需验证和附件校验；缺少本地包本身不构成阻塞。

## 发布与读回

1. 按项目需要固定版本标签或等价的源码标识。支持草稿时先建草稿并记录稳定 ID；平台不支持时，按既有流水线保留等价的发布前验证关口。重用已创建的候选对象。
2. 上传所需附件，核对远端完整清单、完成状态、名称、大小及 SHA-256。可使用可信平台返回的内容摘要；摘要缺失时下载远端文件计算，不能用同名同大小代替内容校验。没有可验证附件的版本按平台要求核对其发布内容。
3. 发布后读回 Release 状态、版本、标签解析后的源码 SHA 或等价来源标识和附件。仅当项目要求时设置并读回 Latest 或相应渠道指针；不能让旧候选覆盖并发发布的新版本指针。

GitHub 操作时再读 [references/github.md](references/github.md)，包含草稿查询与超时恢复细节。其他平台沿用其工具和状态模型。

## 中断与完成判据

| 遇到的情况 | 下一步 |
| --- | --- |
| 创建、上传、公开或推送超时 | 先按稳定 ID、版本、标签和远端 ref 读回，再决定补做；不盲目重复创建或覆盖 |
| 检查失败、来源不符或附件摘要不符 | 停止公开，保留证据，修复并重新验证受影响步骤 |
| 认证、审批或外部服务阻塞 | 保留成果并报告具体阻塞与恢复入口；结果仍未知时不宣称失败或成功，不无限重试写操作 |
| 仅完成构建、上传或草稿 | 报告实际阶段；不称为“已发布” |

完成后简要交付版本、源码提交、必需 CI、Release 链接，以及可下载产物链接（如有）和重要未测项。工作区或分支清理仅按项目约定处理本次已合并且不再需要的内容，保留用户数据。
