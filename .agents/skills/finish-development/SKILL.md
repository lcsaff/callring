# 普通开发收尾

完成已确认开发范围内的验证、提交、集成、推送与 CI 确认。本技能自包含，不要求另一个技能或指定文档作为执行前提。

## 触发边界

- “开发完成”“收尾”“提交并合并”“推送代码”且没有发版要求：使用本技能。
- 明确要求发布版本或续办已授权发布时，本技能不适用。
- 单独修改版本、编译 Release 变体或生成本地安装包，按对应配置或构建任务处理，不据此推断用户要求公开发布。
- 收尾完成后可以交付最终提交及有效证据；不将普通收尾结果描述为已经发布版本，也不自动调用其他流程。

## 收尾步骤

1. 从用户指令、工作区差异、分支和远端确认本次范围与集成目标，不默认 main 或特定托管平台。审查差异并同步受影响的说明；保留其他任务的改动，不全量暂存、不重置或清理工作区来凑出干净状态。
2. 从构建脚本、测试配置和 CI 定义定位可执行检查，按变更风险选择适用项。记录源码、命令、退出码和未测项，区分实际执行、有效缓存和未执行；纯文档检查内容、链接与差异，不额外运行应用构建。
3. 仅提交本次范围，执行已确认的集成方式。核对最终源码；合并或修复改变提交时，重新确认所需验证，不能用其他提交的证据替代。目标或方式缺失时先完成可独立准备的工作，不猜测远端或目标分支。
4. 推送已确认的远端，等待并核对最终提交的必需 CI。没有配置 CI 时如实注明，不虚构通过结果。已有授权和集成方式无需重复确认；确有外部阻塞时保留成果并说明剩余步骤。
5. 仅清理本次已合并、确认不再需要且允许清理的分支，保留工作树数据。报告提交、集成、推送、CI 与重要未测项的实际结果。

## 完成边界

普通收尾不自动递增版本，不创建发行标签、发布说明或发行附件，不创建或公开 Release。统一验证门即使构建了 Release 变体，也只作为验证产物，不构成发版。
