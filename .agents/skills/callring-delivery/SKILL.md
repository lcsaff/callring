# 普通开发收尾

完成开发范围内的验证、提交、集成、推送与 CI 确认。具体命令和项目约定读取根目录 AGENTS.md 及其指向的 PROJECT.md，不在本技能维护第二份版本或发布规则。

## 触发边界

- “开发完成”“收尾”“提交并合并”“推送代码”且没有发版要求：使用本技能。
- “发 Release”“发布新版本”“发版”，或续办已有明确授权的发布：由 `publish-release` 全程处理，包括其必要的验证、提交与集成；不再并行或串行启动一轮普通收尾。
- 单独修改版本、编译 Release 变体或生成本地安装包，按对应配置或构建任务处理，不据此推断用户要求公开发布。
- 用户在普通收尾后追加发版要求时，转入 `publish-release`；交接最终提交及有效证据，不把之前的收尾结果直接当成已发布。

## 收尾步骤

1. 检查工作区、分支和远端，划定本次变更，审查差异并同步必要文档。保留用户和其他任务的改动，不全量暂存、不重置或清理工作区来凑出干净状态。
2. 按 PROJECT.md 运行适用的验证与风险专项，记录源码、命令、退出码和未测项。区分实际执行、有效缓存和未执行；纯文档按项目规定检查内容、链接与差异，不额外运行应用构建。
3. 仅提交本次范围，按项目约定集成目标分支。核对最终源码；合并或修复改变提交时，重新确认所需验证，不能用其他提交的证据替代。
4. 推送约定远端，等待并核对最终提交的必需 CI。已有授权和项目已定的集成方式无需重复确认；确有外部阻塞时保留成果并说明剩余步骤。
5. 按约定清理本次已合并且不再需要的分支，保留工作树数据。报告提交、集成、推送、CI 与重要未测项的实际结果。

## 完成边界

普通收尾不自动递增版本，不创建发行标签、发布说明或发行附件，不创建或公开 Release。统一验证门即使构建了 Release 变体，也只作为验证产物，不构成发版。
